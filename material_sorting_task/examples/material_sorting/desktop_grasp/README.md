# 桌面双臂抓取与柔顺控制

桌面抓取模块服务于任务一和任务三的桌面目标获取。它使用 RGB-D 世界坐标中心、箱体方向和当前关节状态计算双臂预抓取姿态，再通过位置接口执行连续接触、有限预紧和抬升。任务二的货架取物不直接复用桌面抓取路径，而由任务二执行器在货架外进行目标对中和靠近。

## 文件职责

| 文件 | 作用 |
| --- | --- |
| `pregrasp_core.py` | 开放预抓取、连续接触、双侧锁定和抬升控制器。 |
| `manual_dual_arm_pregrasp.py` | 双臂预抓取姿态和联调辅助。 |
| `manual_dual_arm_to_shelf.py` | 桌面到货架的联调工具，不是正式 Client 入口。 |
| `semantic_target_locator.py` | 目标检测和任务语义的桌面定位辅助。 |
| `target_metadata.py` | 目标尺寸、方向和抓取元数据。 |

## 抓取流程

```text
稳定 RGB-D 目标中心 + 方向
              |
      双臂 IK / 预抓取位姿
              |
        夹爪完全张开
              |
       两侧连续向内靠近
              |
  腕部姿态/速度/effort 接触证据
              |
       bilateral lock + preload
              |
        缓慢抬升并保持
```

当前方案是基于 ROS 2 位置控制接口的客户端导纳式“伪柔顺”，不是底层力矩控制。系统记录左右腕部第六关节的位置、速度和 `effort` 基线；根据相对姿态变化、effort 变化和 Server 可用接触信号判断接触。检测到单侧先接触时，控制器限制单侧继续推进，等待双侧证据收敛。

## 关键控制策略

- 预抓取保持两个夹爪完全张开，防止提前碰撞目标。
- 采用连续小步靠近，不使用大距离跳变。
- 双侧接触前允许有限的 1 mm 步进搜索，最大搜索范围受限。
- 接触锁定后执行有界预紧，预紧失败不会无限等待。
- 抬升阶段只调整升降轴，保持双臂和夹爪目标。
- 任务一、任务三共享抓取基础，但放置和返回由各自执行器控制。

## 参数与调试

正式参数应集中在执行器和控制器中修改，不要在联调脚本里另造一套常量。调试时记录：目标中心、左右腕部状态、接触阶段、预紧阶段、抬升高度、失败原因和最终夹持姿态。

被动指标脚本只订阅反馈和日志，不发布任何机器人命令。它记录的 `/joint_states` `effort` 是 MuJoCo 执行器广义 effort，不应直接写成指尖力（牛顿）。

当前控制参数的含义如下，具体数值以 `pregrasp_core.py` 和执行器实现为准：

| 参数组 | 作用 | 调节原则 |
| --- | --- | --- |
| 预抓取偏移、夹爪开口 | 保证目标两侧有足够进入空间 | 先保证双臂不碰桌面和目标，再缩小误差 |
| 接触步长、最大搜索距离 | 处理标定误差和单侧先接触 | 只允许有限小步搜索，不能无限向内推进 |
| wrist effort 基线、滤波窗口 | 判断接触和抑制反馈抖动 | 每次新目标/新尝试重新建立基线 |
| 双侧锁定和预紧上限 | 保持目标而不过度挤压 | 预紧超时或证据不闭合时安全停止 |
| 抬升高度、抬升速度 | 将目标脱离桌面并保持夹持 | 抬升只改变升降轴，双臂目标保持不变 |

抓取指标可使用 `scripts/record_grasp_metrics.py` 和
`scripts/plot_grasp_metrics.py` 被动记录和绘图；这些工具不发布控制命令。指标报告应明确
`effort` 是仿真关节执行器广义 effort，而不是牛顿单位的指尖力。

## 安全边界

1. 目标中心质量为 `bbox_depth_center` 或方向不确定时，不得直接作为最终抓取锁定依据。
2. 双臂命令必须经过长度、有限值和工作空间检查。
3. 预紧、抬升和回撤都有时间/位移上限。
4. 接触、碰撞或输入新鲜度检查失败时保持最后安全姿态并停止推进。

## 联调命令

```bash
MATERIAL_EXECUTION_MODE=pregrasp_only bash scripts/run_client.sh
MATERIAL_EXECUTION_MODE=contact_only bash scripts/run_client.sh
MATERIAL_EXECUTION_MODE=lift_only bash scripts/run_client.sh
```

以上模式会产生真实机械臂运动。测试时只能保留一个 Client 和一个机械臂控制源。

`manual_dual_arm_pregrasp.py`、`manual_dual_arm_to_shelf.py` 只用于联调和参数观察，不应与
正式 `client_task.py` 并行启动。发生输入过期、碰撞风险、工作空间越界或接触证据失败时，
执行器保持最后安全姿态并停止推进；测试结束后重启 Server 恢复初始场景。
